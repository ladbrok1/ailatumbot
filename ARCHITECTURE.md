# AILatumBot — Архитектура переработана

## Проблема (было)
- LLM генерировал бесполезные советы на основе сырых JSON данных
- Диалог не контекстный — бот не помнил предыдущие запросы
- Анализ лежал на плечах GPT/LLM вместо структурированной логики

## Решение (есть)

### 1. **Данные течют правильно**
```
Telegram → Bot → Henrik API (20 матчей) → Parser → DB → Smart Analyzer → User
```

### 2. **Слои обработки**

#### A. Parser (`parse_matches`)
- Извлекает из Henrik API: K/D/A, урон, карту, агента, результат
- **Защита**: проверяет типы, fallback'ит на "unknown"
- **На выходе**: список структурированных матчей

#### B. Analytics (`compute_analytics`)  
- Вычисляет **реальные метрики**:
  - Win Rate (% побед)
  - Avg KDA (среднее K/D/A)
  - Main Agent + Main Map
  - Recent Form (последние 5 матчей)
- **Не галлюцинирует** — всё из реальных данных

#### C. Storage (`save_parsed_data`)
- Сохраняет профиль, аналитику, историю матчей в БД
- Позволяет **отслеживать прогресс** игрока со временем
- Follow-up запросы используют кэшированные данные

#### D. Smart Analysis (`format_analysis`)
- **Вместо LLM**. Выводит:
  - Статистику (матчи, винрейт, KDA, агенты, карты)
  - **Конкретные рекомендации** на основе цифр:
    - Если WR < 45% → "Меняй стратегию"
    - Если KDA < 1.0 → "Работай над позиционированием"
    - Если KDA > 1.5 → "Сильный фраг, стабилизируй"

### 3. **Диалоговой контекст**

**Flow**:
1. `/трекер aisokuro#ako` → парсим, сохраняем, выводим краткий анализ
2. `скинь все` → ищем последний RiotID в чате, выводим полный отчёт
3. `по трекеру скажи какие показатели` → то же самое

**История чата**: сохраняется в БД → бот помнит, к кому ты обращаешься

### 4. **DB структура**

```sql
player_profiles     — профиль (ранг, MMR, регион)
match_history       — каждый матч (K/D/A, агент, карта, результат)
player_analytics    — агрегированные метрики
```

### 5. **Когда использовать LLM**

LLM всё ещё используется для:
- Обычного диалога (`@bot привет`)
- Вопросов без статистики
- Расширенного анализа (если нужно)

**Но**: для трекера используется **Smart Analysis** вместо LLM → надёжно, быстро, без галлюцинаций.

## Улучшения vs Было

| Было | Есть |
|------|------|
| LLM парсит JSON → выдумывает | Parser → Analytics → DB |
| "Рекомендации" = общие фразы | Рекомендации на основе цифр |
| Нет контекста диалога | Контекст через историю чата + БД |
| Каждый запрос к Henrik API | Кэширование в БД, follow-up быстрый |
| Нет истории | Есть player_profiles + match_history |

## ✅ Новые команды (реализовано)

### /help
Справка по всем командам с примерами.

### /tracker [name#tag]
**Анализ профиля** (Smart Analysis — без LLM галлюцинаций):
- Статистика (матчи, WR, KDA)
- Main Agent & Map
- Рекомендации на основе цифр

Follow-up:
- `скинь все` → полный отчёт
- `какие показатели` → все метрики

### /progress [name#tag]
**Трекинг прогресса** за последние 30 дней:
- Изменение винрейта (📈 вверх, 📉 вниз, ➡️ без изменений)
- Изменение KDA
- Количество сыгранных матчей
- Середина периода для отслеживания динамики

```
@bot /progress aisokuro#ako
→ Было: WR 52%, KDA 1.2 | Стало: WR 54%, KDA 1.35
→ 📈 +2% WR, +0.15 KDA (улучшаешься!)
```

### /vs [name1#tag1] vs [name2#tag2]
**Сравнение двух игроков**:
- Винрейт (% разницы)
- KDA (разница)
- Avg Kills/Deaths
- Итого матчей
- Вывод (кто сильнее или "близко")

```
@bot /vs aisokuro#ako vs другой#игрок
→ ⚔️ WR: 54% vs 48%
→ KDA: 1.35 vs 1.1
→ 🏆 aisokuro#ako явно сильнее
```

### /alert [name#tag] [wr|kda] [<] [threshold]
**Оповещения** при изменении метрик:
```
/alert aisokuro#ako wr < 45     → оповещение если WR упадёт ниже 45%
/alert aisokuro#ako kda < 1.0   → оповещение если KDA упадёт ниже 1.0
```

### /alerts
**Список твоих оповещений** с текущим статусом.

---

## 🔔 Система оповещений

**Как работает:**
1. Устанавливаешь: `/alert aisokuro#ako wr < 45`
2. Оповещение сохраняется в `player_alerts`
3. Каждый раз, когда запрашиваешь `/tracker`:
   - Бот проверяет все оповещения
   - Если метрика прошла под порог → **оповещение сразу же в чат**

**Типы оповещений:**
- `wr_below` — винрейт упал ниже порога
- `wr_above` — винрейт поднялся выше порога (премиум)
- `kda_below` — KDA упал ниже порога

---

## 📊 Система сохранений (Snapshots)

Каждый раз, когда используешь `/tracker`, сохраняется **снимок** в `player_snapshots`:
- `win_rate`, `avg_kda`, `total_matches`, `snapshot_date`

Это позволяет `/progress` показать **реальный тренд** вместо случайных чисел.

